# マージ済みブランチの後始末

PRが`develop`へマージされ、役割を終えたローカルfeatureブランチを安全に片付ける。
削除は破壊的操作になりうるため、**マージ済みのみを許す安全削除を基本**とし、強制削除（`-D`）は承認を得てから行う。

## 前提と方針

- 統合先ブランチは既定で`develop`（フローが異なる場合はマージ先に読み替える）。
- 変更を加えるのは**ローカルブランチのみ**（リモートは確認のため読み取るだけ）。
- 破壊的操作（`-D`強制削除）は**実行前に承認を取る**。

## ワークフロー

### Step 1: 現在の状況確認

```bash
git branch --show-current
git status --short
```

- 現在のブランチが`develop`／`main`の場合は、後始末対象のfeatureブランチがどれか不明。**どのブランチを削除するかユーザーに確認**する。
- featureブランチ上にいる場合、それが後始末対象。未コミットの変更が残っていれば、削除前に扱い（コミット要否）を確認する。

### Step 2: 統合先（develop）へ移動

削除対象のブランチ上からは自身を削除できないため、先に`develop`へ移動する。

```bash
git checkout develop
```

### Step 3: developをマージ済みリモート状態へ更新

ローカル`develop`が古いと、Step 5の安全削除が「未マージ」と誤判定される。`--ff-only`で履歴を壊さず最新化する。

```bash
git pull --ff-only
```

### Step 4: リモートに同名ブランチが無いことを確認

```bash
git ls-remote --heads origin <feature-branch>
```

- **同名ブランチが無い** → ローカル削除OK。Step 5へ進む。
- **同名ブランチが有る** → ローカル削除しない。リモートにまだ同名ブランチが残っている旨を報告して停止する（後始末の前提が整っていない）。

### Step 5: ローカルfeatureブランチを安全削除

```bash
git branch -d <feature-branch>
```

- `-d`は**マージ済みのブランチだけ**を削除する安全オプション。成功すればここで完了。
- **失敗した場合**（"not fully merged"等）は、squash／rebaseマージでコミットが`develop`履歴に同一の形で残っていないことが主因。その理由をユーザーに説明し、**本当に破棄してよいか確認してから**`git branch -D <feature-branch>`（強制削除）を実行する。勝手に`-D`しない。

### Step 6: 結果の報告

```bash
git branch
git log --oneline -1
```

削除したブランチ名・現在地（`develop`）・残ったローカルブランチを報告する。

## 注意

- `develop`以外（例: `main`直マージ運用）の場合は、Step 2・3のブランチ名を読み替える。
- このスキルはgit操作を実行するが、**安全削除（`-d`）以外の破壊的操作は必ず承認を得る**。
